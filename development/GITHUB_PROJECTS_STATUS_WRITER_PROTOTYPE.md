# Projects status writer: review prototype

This branch contains a **disabled and unwired prototype** for one controlled test of existing issue #4 on `hva73/1`. `LIVE_WRITE_ENABLED = False` is hard-coded. No workflow invokes the prototype. Do not change that flag or wire it to Actions based solely on this document.

The prototype accepts only Backlog ↔ In progress and requires the caller to provide the existing authenticated, unedited-comment validation, a protected one-time journal claim, and serialization of all cooperating requests. It verifies owner, project, active item, issue identity, unique Status field and desired option, checks expected status, obtains a confirmed claim, and revalidates comment and board before attempting a single parameterized GraphQL mutation. It performs readback, treats an unknown mutation/readback outcome as uncertain, and never retries automatically. Thirty-three local tests across the prototype, runner, audit and existing checks passed. GitHub Actions run 42874922121 also ran the same mocked suite without a Projects credential. A disabled runner connects the existing validator, journal claim and Issue audit in isolated tests. All mutation responses in these tests were simulated. No live Projects write was made.

## Mandatory remaining work before any live write

1. Review and integrate the disabled runner into a trusted, manually gated entrypoint. Test trusted event identity, journal protection and reconciliation, exactly one shared concurrency group for cooperating writers, and authenticated Issue audit comments for success, conflict and uncertain outcomes. The runner connects the existing validator, journal and a fixed-message Issue audit in local tests, but does not provide an Actions entrypoint or serialization. The audit has not been live-tested, and failures before the first successful comment validation currently need workflow-level reporting.
2. Protect `codex/escape-development`, workflow changes, and the secret. An Actions token with `contents: write` has repository-wide scope. Test the actual protection with the identities that will execute; branch protection is not a substitute for secret and workflow review. No new PAT is assumed.
3. Define the allowed transition and intended issue state before presenting the specific first real test for separate owner approval. Read the current status immediately before review. One write only; no automatic rollback or replay. If the outcome is uncertain, stop and independently reconcile the item and journal.
4. Handle manual and external edits explicitly. GitHub's documented mutation input has no expected-current-value or version field; this prototype cannot guarantee that a human change immediately after its last read will not be overwritten. Restrict other writers where possible and agree on an operational single-writer/maintenance procedure; disclose the residual race. Readback can detect some conflicts but cannot prevent or always detect an overwritten concurrent change. If the requirement is zero lost manual changes, do not enable this writer with the current API.
5. Separately verify both actual agent paths, PAT write capability, error reporting and post-write readback. The two connections share a GitHub identity and cannot be reliably distinguished by the currently observed IDs. Neither production deployment, trading, nor trade mandates are part of this task.
